## The instrument (changes from P-148)

Unchanged from P-148: the motion hold, Web Animations and SMIL paused and re-paused before every shot, the settle step
(shots 250 ms apart until two in a row are equal outside the masks, at most 8), the masks (hero clock +4 CSS px; in the
Simulator the screen outside the page viewport), the footprint F (deck box + 24 CSS px, clipped; a mask meeting F is
dropped), the positions (top, enter, inview, leave), the modes (rest, the 10-frame scripted swipe), the Simulator
calibration, the null arm N0 (an empty `<style id=dc-arm>`).

What changes: the **stop** replaces the triple (`px149-run.mjs`). One stop = one position x mode, in one hold:

| step | shots | what happens before the shot |
|---|---|---|
| settle | f1 | P-148's settle; f1 is the settled shot |
| fresh A/A pair 1 | f2 | N0 on, 2 frames, armWait, re-pause |
| | f3 | N0 off, same steps |
| fresh A/A pair 2 | f4 | N0 on |
| | f5 | N0 off |
| fresh A/A pair 3 | f6 | N0 on |
| R3 (part R and Simulator only) | f7 | N0 off: R3's base |
| | a | R3 on, 2 frames, armWait, re-pause: R3's arm |

- **A/A pairs** are (f1,f2), (f3,f4), (f5,f6): three disjoint pairs, each "shot, style toggle on, shot", the exact steps
  of the R3 pair (f7, a). The toggled style is empty, so both shots of a pair are base shots; no real arm has run in the
  page's hold before them (N4). Why the empty toggle and not two plain shots: P-148's G5 failed with N0 at T2 in 66
  Chrome triples, so the toggle itself may move pixels; an A/A without it would leave that motion out of the envelope and
  count it against R3.
- **Pair 1 starts from the settled shot (rev 1.1 N4).** f1 has no N0-off toggle before it; pairs 2 and 3 and R3's base
  f7 each follow an N0-off toggle. So pair 1's first shot was taken after the settle wait, the others after a toggle.
- **R3's pair comes last** in the stop, and R3 is removed before the hold ends. Nothing is shot after R3.
- **armWait** as P-148: 50 ms Chrome, 150 ms Simulator. Geometry (GEO) is read at every shot. Held-callback counts are
  kept per phase (settle, each N0 on, each N0 off, R3).
- **Locator** (after the last shot, before the hold ends, descriptive): the envelope's pixels per 64x64 CSS px tile; for
  the 5 tiles with the most pixels, `document.elementFromPoint` at the tile's strongest pixel (element and parent, tag,
  id, first two classes). It reads no style and changes nothing; it is not a cause.
- **Descriptive `spanAA`** (part R and Simulator): f1 vs f7, both N0-off, about 6 steps apart; reported, never scored.
- **Saved shots** (`out/deck-contain/p149/px149-shots/`, `px149-sim-shots/`): an unstable stop's pair with the most A/A

## Rules (frozen; `px149.mjs`, scorer `score-p149.mjs`, self-test `selftest-p149.mjs`)

A pixel's level is its largest per-channel difference. Fill or edge as P-148 (3x3 neighbourhood in the base within 2
levels = fill; `research/pixel-tolerance/README.md` §1).

**Envelope.** env(p) = the largest level at pixel p over the stop's three fresh pairs (fix-nav-morph's v9.3 proposal,
`fixes/nav-hit-cache/README.md` lines 1450-1451: "the max over all A/A pairs ... fail T2 only when they go beyond that
envelope"). Differences from that proposal (rev 1.1 N3 names all of them):
- the max is taken **per pixel**, not as one edge level and one cluster size per stop: R3 may move a pixel only as far as
  the A/A moved that same pixel. Stricter in place. With only 3 pairs, sparse A/A speckle samples few pixels, so R3's own
  speckle mostly lands outside the envelope: a T2 label at <= 8 levels, counted above 8. Conservative;
- the pairs are **within one load and one hold**, not 6 interleaved loads per arm;
- there are **3 base-only pairs per stop**, not 3 per arm;
- R3 is judged by the **T2 numbers** (fill, edge, share, area, all-pixel shade), not by an edge level plus a cluster size;
- a **stability cap** on the blind set (below) is added.
**Blind pixels (rev 1.1 N2).** A pixel whose envelope is above 8 levels is blind: R3 is not judged there toward fill,
share or area (as P-148's "A/A > 8" rule); only the all-pixel shade limit still applies. The blind set is capped at
0.01 % of the frame by the stability rule below, and R3's levels there are reported (`blindAboveEnv`, `blindMax`).

**Stable stop.** All of:
1. settled (P-148's G2);
2. three fresh pairs exist;
3. blind pixels (env > 8) <= 0.01 % of the frame (P-148's G4 number, applied to the blind set: at 430x932 DPR 3 that is
   360 device px = 40 CSS px, 2 % of T2's 2,000 CSS px area);
4. no geometry move between f1 and any of f2-f6 (GEO, 0.02 px; P-148's G6).
A/A at 1-8 levels inside the envelope is allowed in any amount: outside the blind set it can only change a T2 label into
T1.

**Stable cell** (part L): all 4 of its rest stops exist and are stable.

**R3 tier at a stable stop** (arm level L(p) between f7 and a):
- **T0**: no pixel differs;
- **T1**: L(p) <= env(p) at every pixel;
- **T2** (memory "illusion must be pixel-identical"; rev 1.1 N1): the largest shade over **every** unmasked pixel <= 128
  (as `px148.mjs` and the lead's P-148 N1 ruling), and over the counted pixels (L > 8 where env <= 8): fill <= 64,
  edge <= 128, share <= 0.5 % of the frame, area <= 2,000 CSS px (the stop's total);
- **T3**: anything else.
Then, as P-148:
- R3 geometry move between f7 and a (deck box, shells, section, next section, document height, scroll): T3;
- reduced motion (primary-rm) not T0/T1: T3;
- motion-only: a swipe stop at T2+ whose rest stop at the same position is T0/T1 becomes T3, **only when the swipe stop
  has at least one counted pixel** (`beyond > 0`: above 8 levels where the envelope is 8 or less, exactly the pixels the
  T2 numbers count). Otherwise the swipe stop keeps its own tier, so neither sub-8 noise nor the blind set (envelope
  above 8, e.g. A/A 9 and R3 10) makes a T3 (rev 1.1 N5; rev 1.2, the lead's ruling on ops-reader-P149's follow-up;
  rev 1.1 had `largestShadeAboveEnv > 8`, which counted blind pixels);
- **held extra**: R3's phase held more page frames + timeouts than the most of the stop's N0-on phases, by more than 2:
  the verdict becomes UNDECIDED-HELD unless something is T3;
- R3 pixels beyond the envelope outside F are counted (`beyondOutsideF`) and stay unmasked.

**A stop is judged** only when it is stable. A registered stop that is missing or unstable is "not judged" and named.

**Verdict** (`score-p149.mjs`, in this order):

| verdict | when | reading |
|---|---|---|
| NO-STABLE-CELL | part L has no stable cell | R3 is not judged; R3 goes to a look proposal with Try-it panels; the Simulator's numbers are descriptive |
| PLAN-MISMATCH | an R file ran a config outside the plan part L gives | the lead rules |
| R3 T3 | any judged stop is T3 (after the rules above) | a look proposal, the lead rules |
| R3 UNDECIDED-HELD | held extra at a judged stop, nothing T3 | the lead rules |
| R3 UNDECIDED-UNSTABLE | any registered part-R or Simulator stop not judged, nothing T3 | R3 goes to a look proposal with Try-it panels; the judged stops are reported |
| R3 T0 / T1 / T2 | every registered stop judged, worst tier | names the Chrome cells and the Simulator states it covers |

**Locator reading** (descriptive, `pattern`): "DPR 3 cells unstable, DPR 1 cells stable", "mobile-emulated cells
unstable, desktop cells stable", "only the mobile-emulated DPR-3 cell unstable", "all four cells stable", "no cell
stable", or "other: unstable <cells>". Per cell: stable stops, pairs with any A/A, pairs above 8 levels, largest A/A
share, largest blind share, largest level, unsettled positions, and the elements at the strongest tiles. None of it is a
cause; a cause claim would need its own card and a reference (CLAUDE.md "Platform claims").

## Known limits (disclosed now)

- **The A/A interval is one toggle step.** Each A/A pair spans one N0 toggle (2 frames + armWait + a shot), the same as
  the R3 pair, but P-148's base vs base-again spanned two. A slower drift could pass the envelope and still be in R3's
  pair; `spanAA` (f1 vs f7) shows such drift and is reported, not scored.
- **"Fresh" means per hold, not per load (rev 1.1 N7).** Within one load, every stop after the first follows earlier
  stops' R3 toggles, and S1's landscape follows all 8 expanded R3 stops on the same page (P-148 gave landscape its own
  session). An R3 after-effect would show up as A/A in later stops; the stability cap bounds it, and the scorer reports
  A/A per stop in run order (`byIndex`: stop, envelope pixels, blind pixels, stable), descriptive.
- **One load per cell and state.** Per-load states (F-294) are not sampled; they cannot enter a pair, because every pair
  is within one load.
- **Rest only in part L.** A cell's swipe stops are first seen in part R; an unstable swipe stop there is "not judged"
  and leads to UNDECIDED-UNSTABLE.
- **No reduced motion in the Simulator**, as P-146 and P-148: reduced motion is judged in Chrome (primary-rm) only.
- **Desktop widths are not judged.** P-148's d860x900 is out of this card's size budget; at widths above 860 R3's media
  query does not match a non-touch desktop at all.
- **The locator names elements, not causes.** `elementFromPoint` gives the topmost hit-testable element at a point,
  which may be an overlay above the painted pixels.
