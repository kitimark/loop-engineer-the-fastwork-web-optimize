# Shared findings: what works, what bites

The team's playbook for fixing scroll and animation jank on this page: techniques that won A/Bs,
pitfalls that cost a review round, and measurement lessons. **Read it before you edit, re-read it when
you resume.** Each entry names its source (topic, incident or review) so you can open the details in
`fixes/<topic>/README.md`.

Live findings from agents who are still working go to the board first:
`node tools/finding.mjs post …` (incident I-013; until it lands, `SendMessage` the lead). The lead folds
them into this file. Only the lead edits this file.

## Techniques that worked

| # | technique | where it won | notes |
|---|---|---|---|
| T1 | **Gate on the same media query as the CSS.** Where CSS already neutralises an effect (phones: scale 1, radius 0), skip the rect reads, the custom-property writes and the easing rAF. | phone-invisible-shrink: mobile 6x fps 66.5 → 71.6; iPhone frames >20 ms 60-64 → 40-43. commission-forced-layout: frames >20 ms 96 → 71 | Copy the query **exactly** from the CSS rule (all comma parts, `hover`/`pointer`). Keep side jobs such as class toggles that other code reads. Re-run the callback on the MQL `change` event and remove the listener on teardown. |
| T2 | **Cache `MediaQueryList` objects.** `matchMedia()` per frame parses the query each time; `.matches` on a cached MQL is live. | phone-invisible-shrink (`oe`/`ce`), commission (`A()`) | Behaviour-neutral, so it's safe everywhere. |
| T3 | **Write only on change.** Keep the last written value of each custom property or style in the closure and skip identical writes. | commission-forced-layout | The cache lives in the effect closure, so a remount resets it. |
| T4 | **Move layout reads off the frame.** Run `Range.getClientRects()` line counting and similar only when an input flips, and let a `ResizeObserver` on the element that reflows cover the rest. | commission-forced-layout (`j`): its forced layout left the LoAF top list | Check that the observer watches the element whose size actually changes (font swap, width, text). |
| T5 | **Composite instead of layout.** Replace animated `width` / `flex-basis` / `margin` / `border-width` with `transform`, `clip-path`, `opacity`; FLIP neighbours with WAAPI transforms. | layout-animations: idle layouts per 5 s 231-330 → 13-16 (hero), 248-279 → 13-16 (carousel) | **FLIP without reads:** in a centred flex row, a word whose width changes by Δ keeps its centre: siblings before it move -Δ/2 and after +Δ/2. Apply the width at once and animate the siblings from `translateX(±Δ/2)` to `none` with WAAPI, using the old duration and easing. Take Δ from widths the code already has, never from `getBoundingClientRect`. Take the sign from the flex container's computed `direction` (and `row-reverse`), never from `html[dir]`: here `.start-selling { direction: ltr }` wraps the hero, so under `html[dir=rtl]` the row-reverse title is still ltr and the flip in layout-animations 03 was correct (review-layout05; the /05 "fix" broke RTL). **Progress bars:** a `--progress` var with `clip-path: inset(0 calc(100% - w) 0 0 round 999px)` (clamps its ends the way `border-radius: 999px` does), `background-size: w 100%` (gradient not stretched), and `w = max(<old padding box>, p*100%)` so 0 % matches. (The claimed "0 % pixel diff at 7 values" is unverified: those shots were blank strips, a clip in viewport instead of document coordinates; re-check pending with the fixed script, layout-animations 05.) **Two animations on one element:** use the individual `translate` property; it composes with `transform`, so a slide and a scale don't overwrite each other. |
| T6 | **Pause off-screen infinite animations per element.** IntersectionObserver (rootMargin `0px`) on the animated element, not the section. | layout-animations (gradient sweep gate), scroll-engine (avatar carousel) | The section-level engine gate (`rootMargin: 100%`) keeps tall sections "active" a full viewport away. Use `0px` only when the paused frame looks acceptable when it scrolls in: the hero accent keeps `100% 0px`, or it could freeze mid draw-out and show blank. |
| T7 | **Replace per-frame threshold rect reads with an IntersectionObserver.** A callback that reads a rect only to test "progress >= x" becomes an IO with a matching rootMargin. | proposed: future `l` / nav `_` `.hero-track` test, rootMargin `-128% 0px 200% 0px` | Open for wave 2. Inside a T9 `measure()` the rect read is cheap (layout already clean), so this mainly saves the `querySelector` + JS: worth it, small. |
| T8 | **Mount hidden heavy DOM lazily.** A panel that is invisible until an interaction shouldn't mount synchronously inside a scroll frame. | proposed, not yet measured: nav-morph topic 13 targets the 42-75 ms LoAF at mount (result pending E1, `morph-panel-lazy-mount/01`) | `requestIdleCallback` after load, sync fallback when it's needed; `loading=lazy` images; pass the shown state down so nested timers pause. |
| T10 | **Cut a blur transition's invisible tail, keeping its curve.** Resample the original cubic-bezier into a shorter `linear()` easing that ends once the blur is under 1 device px; keep the original declaration first as a fallback. | large-area-blur, future-card reveal 1.6 s → 0.9 s: iPhone paint area 53.6-54.7 → 48.1-49.2 Mpx, 402x857 panel repaints 4 → 2 per run | Chrome 6x can't see it (P5). |
| T11 | **Hit-test without writes.** A toggle hit-test (inline `pointer-events:none` on your own root, then `elementFromPoint`, then restore) restyles the whole subtree twice per frame, because the property inherits. Use `document.elementsFromPoint()` and skip your own subtree (except descendants with explicit `pointer-events:auto`): same answer, no writes. | nav-hit-test: mechanism by code (2 inline pointer-events writes per scroll frame → 0; parity probe 0/1690 mismatches). Timing void: frames >20 ms 98 → 62, fps 69.1 → 75.3 were contaminated (load 11.3-17.5) and old-tools; gain pending the wave-1 combined A/B | |
| T12 | **Scroll-driven exit instead of a per-frame rect read.** For a subject taller than the viewport, `view-timeline` on `.hero-track` + `animation-range: contain 0% contain 100%` equals the JS formula `1 - clamp(-top, 0, h - vh) / (h - vh)`. The `animation` shorthand resets `animation-timeline` / `-range`, so declare the longhands **after** it, with comma lists aligned to the animation names. Keep the JS path as a fallback (`@supports`). | hero-exit-scroll-timeline: iPhone 26.6.1 parity vs baseline, copy opacity .901/.501/.03 at .1/.5/.97, cue blur 1.78 vs 1.79 px | See P3 (Safari custom-property keyframes). |
| T9 | **Engine: two-phase frames, debounced height-only resizes, finish on deactivate.** One rAF per frame while scroll events arrive (as before). New opt-in contract: `dE({measure(f), mutate(m, f)})` runs all measures, then all mutates, in one rAF; `f` is a lazy per-frame `{vh, vw, y}`; `mutate` returns `true` to keep easing, which replaces the callbacks' own rAF trampolines. Legacy `dE(fn)` callbacks run first. A height-only `resize` (iOS toolbar) runs one frame 120 ms after the last event; an effect going inactive runs once more so its final state is right. | scroll-engine (wave 2): parity clean on 39 steps; A/B within noise on its own | 5 of 8 callbacks were rAF trampolines (`o = () => t ||= rAF(a)`): their work ran a frame late, each forcing layout after the previous one's writes. On phones T1 already emptied most of them, so batching alone moves forced ms only ~25 %. Anything that removed its own rAF tail (T1) relies on the final-position frame. |

## Pitfalls (each cost a review round or a wrong number)

| # | pitfall | source | how to avoid |
|---|---|---|---|
| P1 | **Replace-all on a minified short name** also rewrites SVG attributes and unrelated scopes: `cy` → `_cy` broke 6 icons' `<circle cy>`, and 3 screenshots didn't show it. | review of commission-forced-layout | Pick a new name that doesn't exist **anywhere in the file** (`grep -c` it first: short names such as `hA`, `hm`, `hr` also exist at module level and get shadowed) and rename only inside your function. Before measuring, run `node tools/fix.mjs diff <topic>` and check that **every hunk sits inside your function**. |
| P2 | **Removing a rAF easing tail changes when side jobs run.** `.pain is-pain-dark` and the hero-track check then update only on engine callbacks. | review of phone-invisible-shrink | Check that the engine fires at the final scroll position (T9), and list the side jobs in your README. |
| P3 | **Safari 26: keyframes that reference an animated custom property resolve against its base value.** | hero-exit-scroll-timeline | Animate the real property in the keyframes, or drive it from JS. |
| P4 | **What costs is a blur value that is *changing*, not `blur(0)` at rest.** `#platform` `filter:none` vs the permanent `blur(0px)` made no measurable paint difference at rest on the iPhone (6 s idle: paints 1676/1766 vs 1809/1762). But WebKit repaints a filtered element's contents on every frame the filter value changes. | large-area-blur (corrects an earlier guess); nav-morph dropped its 5392 change | Shorten or skip blur *transitions* (T10); don't spend a patch on a resting `blur(0)`. |
| P5 | **Chrome CPU throttling can't show GPU raster cost** (blur, backdrop-filter, big layers). | large-area-blur | Needs the scripted iPhone check; mark it "iPhone pending" when the phone is away. |
| P6 | **The screenshot diff covers 3 points only**; small icons and off-shot sections escape it. 0-0.4 % is countdown/orbit/sweep phase noise. | commission review, layout-animations | Frozen-frame checks of what you changed, plus the P1 hunk check. |
| P8 | **A nested `backdrop-filter` inside a parent that already has one is not a visual no-op.** Removing the lang switch's backdrop inside the nav made the EN pill visibly darker (screenshot diff 0.51 %, exactly the pill rect). | large-area-blur, reverted | Keep it, or compensate the colour and prove it with a frozen-frame diff. |
| P9 | **A no-op Svelte state write still costs.** `set` compares with `===`, so `z(T, [], true)` with a fresh `[]` always triggers: it opens a batch and re-runs derived each-blocks, every frame. | pain-offscreen-notes (`d`, JS 4730, via chunks/BSBv9QXB.js 1229-1236) | Guard the write (`s(T).length === 0`), or keep a constant empty array. Look for `z(x, [` / `z(x, {` inside per-frame callbacks. |
| P10 | **Check the topic premise with a counter probe before fixing.** TOPICS row 11 said the pain interval adds hidden notes on phones; the code shows `le` returns early on matchMedia (JS 4595) and the probe counted extraNotes = 0. (Its MutationObserver watched `.pain-notes-stage`, but the notes render in `.pain-canvas`, so it was blind: 0 on desktop while 11 notes were added. Check that a counter can fire before trusting its 0.) The real cost was the per-frame scroll callback. | pain-offscreen-notes | Probe first: MutationObserver plus wrapped `getBoundingClientRect` / `querySelector` / `setInterval` counters, under the lock. |
| P11 | **Pausing an infinite animation off-screen shifts its phase.** The patched page resumes at a different point in the loop than the always-running baseline, so the screenshot diff rises above the 0.4 % noise line with no visual change (layout-animations: 0.56 %, only the gradient inside the titles). | layout-animations | Crop and inspect the diff before calling it a regression; say so in the README. |
| P12 | **Keep a `dE` registration even when its callback becomes a no-op.** `dE` also pauses the scene (`data-start-selling-scene`, `animation-play-state: paused`) and sets `data-start-selling-render=deferred` (`content-visibility: auto`); unregistering loses both. | hero-exit-scroll-timeline (from code reading at design time, JS 2703/2765/2774-2779 + CSS 11754-11762; the variant was never built: row hero-exit-scroll-timeline/08) | Make the callback `() => { mode || work(); }`, don't remove the call. |
| P13 | **iPhone Safari caches `/_app/immutable/*`** (immutable headers): after an overlay edit it kept serving the old CSS, so a fixed bug looked unfixed. | hero-exit-scroll-timeline | Re-test on a new port, or serve with `serve.mjs --no-cache`. |
| P7 | **Shared scratch files collide** between agents. | I-006 | `<scratchpad>/<topic>/`. |
| P14 | **A screenshot clip after a scroll can be a blank strip, and blank equals blank.** `Page.captureScreenshot` `clip` is in document coordinates; a viewport rect taken after scrolling captures empty page, so every "0 %" diff after a scroll was a false pass. | layout-animations frozen-frame checks (carousel, fee bar) | Add `scrollX`/`scrollY` to the clip, and fail a shot with no colour range (`VISUAL-BLANK`) before diffing. |

## Couplings (change one, check the others)

- **Morph IO `dN` (JS 13082, rootMargin 200 %)**, about 3 screens before the page end, arms the blocking wheel/touchmove listeners (topic 6) **and** mounts the morph panel (topic 13, 42-75 ms LoAF), whose second countdown `cD` (JS 13160) animates while invisible (topic 1 part 2 must honour the `active` getter nav-morph passes). Any change to that callback touches topics 1, 6 and 13.

## Measurement lessons

- **Where the remaining jank is** (mobile 6x, plain baseline, scroll-engine's LoAF attribution):
  - **Frames >50 ms, per run:** gtag `onscrollend` ~65 ms (vendor, not fixable here); the morph IO callback at JS 13083 (`u = isIntersecting; z(b, !0); I()`, ~55 ms with ~20 ms forced: topic 13, T8); `iE` ~55 ms over 3 frames.
  - **Frames >20 ms** (~100 per run, p95 25.7 ms) are not LoAF-visible, but that does **not** make them style/paint: LoAF only reports frames >= 50 ms, and CPU throttling slows the whole renderer main thread, script included (corrected by the architecture team, `research/architecture/README.md`, `render.md`). Old traces show style recalc (`UpdateLayoutTree`) at ~2x script time, so "mostly style" is likely but unproven until per-frame attribution exists (topic N1 `frame-attribution`, I-018). Likely movers: inherited custom properties written every frame (register them `inherits: false`, write them on the element that uses them: ~850x cheaper per change on a 1,000-element tree, web.dev), declarative animations (scroll timelines, WAAPI with `linear()` springs). T3 (write only on change) saves only call overhead in Blink, which already skips identical writes. Engine batching alone won't move them.
  - **Host load inflates the jank metrics** (`research/measurement-parallelism/`): on the unchanged baseline, frames >20 ms were ~66 at load1 < 6 vs 96-103 at load1 6-15 (fps 74 vs 67-69). Within one A/B session load barely matters (r = 0.13), but never compare an A/B measured at load > 6 with the A/A floor (measured at load 3-6). On macOS the load average counts memory stalls: check CPU idle too (I-016, I-017).

- **Scripted scrolls can't see input-handler fixes.** `iphone.mjs scroll` and Chrome's A/B scroll by script, not touch, so making touchmove/wheel passive shows as flat (nav-morph iPhone: fps 52.7 vs 52.5). Measure those with a CDP `Input.dispatchTouchEvent` ack-latency probe, or the finger test.

- **Host load decides what an A/B can show.** At load above about 6, ranges overlap. Quote verdicts against an A/A at similar load, and the integrator re-measures a whole wave on a quiet machine (`research/measurement-parallelism/`).
- **Frames >20 ms and forced layout move first.** fps and >50 ms frames need bigger changes or quieter hosts to leave the noise.
- **Forced layout moves to the next reader instead of disappearing.** Removing pain's rect reads (333 → 0 per pass) cut `iE`'s forced layout from 46-52 to 4-7 ms, but the next reader (future `l`) rose from 15-20 to 25-30 ms: net -24 ms, within noise. A win shows up once all readers in the frame are gone or batched (T1, T7, scroll-engine's measure/mutate split); expect the combined wave to beat the sum of single A/Bs.
- **Idle costs need an idle phase** (I-002). Until it lands, a short own CDP probe is fine; document it and re-run the official tool later.
- **The scripted iPhone check works:** 3 runs each, alternating (ABBA), plain http (I-003), frames >20 ms / >34 ms as the metrics. It runs in parallel with Chrome.
- **Hold `chrome-measure` only while a run executes.** Short test jobs use the short lane (I-007, I-011).
