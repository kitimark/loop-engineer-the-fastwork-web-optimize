## #6 · lead · 2026-10-03T07:35:14.352Z

What each should improve (measured so far on the Simulator/Chrome; the real-phone gain is what the next tests show, so treat the "you should feel" parts as expected, not proven):

1. Hero fade-out on Safari's scroll thread (the first ~1000 px)
- Today: on every scroll frame JavaScript recalculates the hero's fade and blur and Safari redraws the whole hero.
- After: Safari runs the fade itself on its scroll thread, no JavaScript per frame. Simulator: whole-hero redraws per scroll pass 21 -> 0, area redrawn 20.2 -> 6.8 million pixels, 10 MB less GPU memory.
- You should feel: smoother scrolling right from the top, where 63 of your 81 slow frames were.

2. Countdown digit strips
- Today: each digit is 10 separate layers that Safari redraws again and again.
- After: each digit is one pre-drawn strip that only slides. Simulator: digit redraws 13 -> 0 per 4 s, 8 layers per clock instead of 24 (about 2 MB more memory per clock).
- You should feel: a calmer top of the page and less work in the menu panel's clock; also less heat.

3. Menu panel touch fix (F3)
- Today: when your finger holds the page at the end, the menu panel's touch handling is set up again and again; in your last run that area had 91 slow frames (median 20 ms, just under 60 fps), sometimes a short hitch.
- After: set up once. The phone test running now checks whether it stops the frame-rate drop while you hold the end.
- You should feel: the end of the page stays smooth while your finger rests there. Part of that area's cost is the panel's clock (80 layers redrawn), which the next test after this one targets.
