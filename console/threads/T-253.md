Answer: the menu centre is its own layer because it overlaps the moving menu columns; the clock only makes it redraw.
- Q1: WebKit's "overlap" rule makes the centre (morph-center) a layer: it sits over the column animation. The clock lives inside it.
- Q1: in the original the clock ticks even while the menu is hidden and redraws the centre ~80 times per 0.45 s; opening creates 80 digit layers, closing deletes them.
- Q2: today's best top bar has 6 layers vs 4, but the extra 2 are plain colour layers with 0 MB, and the bar no longer redraws while the menu moves.
| Simulator count (layer = one compositing border) | original (v0) | today's best (g0.0f) |
|---|---|---|
| top bar layers / MB, menu open | 4 / 12.6 | 6 / 1.0 |
| whole page at the end, menu closed / open | 29 / 110 layers | 53 / 53 layers |
| layers created + deleted per open/close | 80 | 0 |
| centre redraws per 0.45 s, closed / open | ~80 / 0 | 0 / ~21 |
- Avoidable, same look: the 3 overlap layers (centre, veil, footer; 7.6 MB closed) go if the columns stop while closed: the "stop columns" proposal (PR-039 option 2).
- That saves memory only; the last phone test (P-169, the flip-frame check) found no shorter frame from it.
- Next idea: the clock on its own small layer while open, so ticks stop redrawing the 5.7 MB centre; it needs a pixel check, else a proposal. Owner: fix-g0-box.
- Not worth it: dropping the language button's own blur (looks different); freeing the hidden menu's layers (cost moves into the first open frame).
- All numbers are Simulator counts (OBSERVED), not timings. Check done: with the clock hidden, the original's centre stops redrawing and the 80 layers never appear.
