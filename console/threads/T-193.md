## #4 · lead · 2026-10-05T10:30:31.023Z

How they work, in short (all OBSERVED in our setup; the article page has the long version):
- Graphics-chip morph: the panel's grow-and-fade was script writing a CSS variable every frame; now a CSS animation of opacity and transform runs it on Safari's compositor thread.
- Opacity is capped at 0.9999, so the layer is never dropped and rebuilt at the end.
- Countdown digits: the ~80 digit layers sat outside the panel's layer, so every panel move repainted them. One CSS rule keeps them inside the panel's own layer, so a move only shifts the finished layer.
- Less style work: one class change at the panel start made the browser restyle about 700 elements (11-14 ms). The rules now match only the panel's own part.
- Touch listeners: the panel added its touch listeners when you got close, which cost one 100+ ms frame. They are added once at page load.
- Pin clamp: the sticky panel's position was computed past the real page end while you pushed further, so the page jumped between two spots. It is clamped to the real end.
- Top-bar fix: a CSS variable was registered as non-inheriting, which Safari handled differently, so the bar stopped following. It inherits again.
- Menu follows your finger (7c/7d): an extra screen of scroll sits after the panel; how far it has scrolled in sets the morph, so your finger drives it.
- At lift-off the finger's speed picks open or closed; 7d lets a fast or long close keep its own momentum.
What you need to do: nothing; ask about any line and I'll go deeper.
