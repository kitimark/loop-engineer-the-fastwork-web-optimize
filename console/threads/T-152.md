## #2 · lead · 2026-10-04T19:07:21.809Z (asks)

Yes: anything that takes over about a minute should run in the background. A command running in the foreground means the agent can't read messages until it ends. The tools can enforce this; I need your OK for one guard.

- Why: an agent only reads new messages between its commands. The full test run (4-5 min), a Mac lock wait (up to 10+ min) or a timing run in the foreground makes it deaf for that long. `test:unit` itself is short (about 5 s).
- Already fixed today (eba686eb): a question to a busy agent now goes to a free one (me or a helper) instead of waiting.
- Proper fix: a Claude Code guard refuses known long commands in the foreground (full npm test, lock holds and waits, timing runs) and says "run it in the background".
- That guard is part of the protected safety layer, so it needs your OK. A tool-builder writes it with tests.
- Until then I add the rule to the agent guide and tell every running agent now.
