Short answer: nobody designed the loop up front; it grew from failures, one rule or tool per problem.
- Day 1: a frozen copy of the page, one A/B tool, and one lock so two Chrome tests never ran at once.
- Then parallel agents in their own git copies, a shared board (status, incidents, findings), and the console for you.
- Each failure became a rule with an enforcer: hooks that refuse risky commands, tests on every tool change, a note in memory with its why.
- Biggest lesson: your thumb, not Chrome numbers, was the real judge; the loop got good once phone tests and blind swipes drove it.
- My view: the method was right but the rulebook grew too heavy; a lighter start with the phone from day 1 would cost less.
