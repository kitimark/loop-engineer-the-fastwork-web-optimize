## #31 · lead · 2026-10-06T09:35:49.457Z

Partly yes: Safari can run some animations off the main thread, but only transform, opacity and filter, which our morph does not use today.
- Already parallel in Safari: drawing (in a separate GPU process) and putting layers on screen (outside the page). Style, layout and painting stay on the page's main thread (WebKit source, RemoteLayerTreeDrawingArea.mm).
- Animations that skip the main thread: only transform, opacity, filter and backdrop-filter (CSSProperties.json). Our panel animates height, width and a clip through a JS value every frame, so all of it runs on the main thread.
- New in Safari 26.4: scroll-driven CSS animations can run in another process (Apple's 26.4 release notes); your phone runs a newer version, 26.6.1.
- Not "everything on the GPU": each full-screen layer costs about 14 MB on your phone (our arithmetic), and re-showing layers looks like what made fix A slower.
- Plan: a new agent rebuilds the panel morph with scale and opacity driven by scroll, after first checking that Safari really skips the main thread for it. It becomes a proposal with a Try-it, pixels shown.
- Still unconfirmed: whether Safari also skips per-frame style work for such animations; that agent's first test answers it.
What you need to do: nothing now.
