## #9 · lead · 2026-10-09T11:46:20.487Z

Update on the late repaint: Safari's code does work the way we guessed; that it causes this exact repaint is still from one test only.
- Confirmed in WebKit's source (Safari 26 branch): the first time Safari draws a photo it may decode it in the background and draw nothing for it yet.
- When that decode finishes, Safari repaints the whole photo. That matches the repaint 1-3 s after the card appears.
- Seen in our setup, one try: making every photo decode during its first draw removed the late repaint and made the reveal frame heavier.
- Still open: why only some photos. g0.0l already decodes the photos ahead, so Safari may have dropped some decoded copies to save memory (a guess, not read in the code yet).
- Next: repeat that test 3 times and count blank photo boxes right after the reveal, then measure the g0.0m fix.
What you need to do: nothing.
