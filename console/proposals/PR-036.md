## Problem

Three bugs of the original site, all while the Join waitlist button fades out at the end of the page:
- The original page, v14 and today's best build g0.0c all have them.
- Edges: the button blurs while it fades. In Safari the blur shows as a dark square block next to the pill's left end, over the language button, with straight top and bottom edges. Chrome shows only a thin sliver in the corners.
- Gap: the space before the button is removed at once (about 0.05 s into the menu's 0.68 s opening), while the button stays visible for about 0.44 s more. So the language button touches the fading button.
- Safari only: the button's side padding is supposed to shrink over 0.68 s, but Safari skips that animation, so the pill snaps narrower at once and the language button jumps about 32 px to the right.

## Idea

Three small style rules, only for this fade:
- Cut the blurred button to its own pill shape while the menu moves, so nothing shows outside its rounded edge.
- Keep the gap until the button has faded out, then close it with the button's last bit of width. On the way back the gap opens first, before the button fades back in.
- Let Safari run the padding animation too: name the left and right padding instead of the combined 'inline' name, which Safari does not animate.
- Chrome already did exactly this.
What you need to do: on the phone, open A and B, scroll to the end so the menu opens, and watch the Join waitlist button and the EN button as it fades. Then pick one.

## Looks the same?

Everything outside the Join button and the gap is unchanged:
- Above the end of the page, the nav is pixel-identical (Chrome, 20 scroll positions each at phone and desktop width).
- The open menu, the closed state and the button at rest look the same as today.
- Reduced motion (the setting that turns animations off) keeps today's behaviour.

## Risk

Low: three style rules on one button and the gap before it; no script change, no new layers.
- Safari's square block: the exact Safari code path is not pinned down yet (OBSERVED in the iOS Simulator only); the fix does not depend on it.
- Safari's skipped padding animation is explained by WebKit's source code (the engine that runs Safari): it does not animate the combined 'inline' padding name.

## Visual difference

- During the fade only: no dark square next to the pill in Safari; its edge is the rounded pill shape.
- The gap between EN and the button stays (4 px on phones, 8 px wider) until the button is gone, then closes.
- Safari: the pill keeps its side padding and shrinks smoothly, as in Chrome, so EN slides instead of jumping.
