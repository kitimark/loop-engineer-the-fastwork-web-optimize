# PR-031: People title: slide the letters instead of re-laying out the line while the faces open (phones)

- by: fix-people-gpu
- area: middle
- topic: people-gpu
- state: accepted
- rev: 2
- proposed: 2026-10-06T17:41:50.334Z
- updated: 2026-10-07T00:09:44.817Z

## Problem

The 'o' in the 'People still need people' title costs a full re-layout on every frame while it opens.
- The 'o' of the second 'people' opens into a row of face photos and closes again (0.92 s).
- Today the browser grows the 'o' box step by step, so it lays out and repaints the title line on every frame.
- Chrome at phone size: 56 layouts while it opens, 59 while it closes.
- iOS Simulator: about 30 layouts and 150 repaints (4.6 million CSS pixels) while it opens.

## Idea

The 'o' box takes its final size at once; the letters beside it slide into place by a GPU move.
- Phones only (860 px wide or less), not with reduced motion.
- The slide has the same length and curve as today's motion (0.92 s).
- Closing runs backwards: the box keeps its open size while the letters slide back, then closes.
- The slide distances come from sizes already in the CSS: nothing is measured on the page.
- When the motion ends, the page is exactly today's.
- Base: today's v10 build with the compositor morph (js file a33a6c7c1f2b, css file 62743920fe1a).
- This change: js file 9e66ff0696b4, css file 592d1f2a8af4 (file fingerprints).

## Looks the same?

At rest it is pixel-identical to today's build, in Chrome and in the iOS Simulator.
- Closed, open, and after scrolling back: identical.
- During the motion letters and faces follow the same path within 0.03 CSS px.
- They are moved as a picture instead of re-drawn at each place, so edges land a little differently.

## Risk

Low; the main open points are the phone check and the base build.
- The letters are wrapped in small spans on phones at runtime; the text a screen reader reads is the same.
- Opened and closed quickly, the slide reverses from where it is, as today's motion does.
- Simulator counts are OBSERVED in our setup; the phone gain is not measured yet.
- If the base build changes, this has to be rebuilt and re-checked.

## Visual difference

- While the faces open (about 1 s), photo and letter edges are slightly softer.
- Chrome: up to 0.35 % of the screen, strongest shade 217 of 255, on the photo edges.
- iOS Simulator: 0.33 %, shade 233.
- This is above the 'looks the same' limit (shade 128 on edges).
- So it is visible in a still frame, which is why this is a proposal.
- In motion it lasts under 1 s.
- While the faces close, the difference is smaller.
- Under 0.04 % of the screen (Chrome), shade up to 212 on a few edge pixels.
- Tried and dropped: the face photos on their own layers did not reduce it (shade 220).
- A/A check (today's build against itself): 0 % in Chrome, under 0.07 % in the Simulator.
- The numbers above count only pixels off by more than 8 shades in both repeats and not in the A/A.
- Nothing changes on screens wider than 860 px, with reduced motion, or for right-to-left text.
