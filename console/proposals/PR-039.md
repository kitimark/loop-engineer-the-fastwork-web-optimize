# PR-039: Menu photo columns: stop holding them in graphics memory while the menu is closed

## Problem

The menu's 4 photo columns use about 15 MB of graphics memory even while the menu is closed.
- Our best build (g0.0f) builds the full-screen menu while the page loads, so opening it later costs nothing.
- The columns slowly slide up and down. While the menu is closed the slide is paused.
- In Safari a paused slide still keeps each column as its own picture in graphics memory, for the whole visit.
- iPhone Simulator: about 15 MB and 6 extra layers (pictures the screen keeps) that nobody can see.

## Idea

While the menu is closed, remove the columns' slide instead of pausing it.
- Safari then drops their pictures from graphics memory.
- When the menu opens, the slide runs again.

## Risk

Low.
- Measured on Chrome and the iPhone Simulator only; the real iPhone has not checked it yet.
- The saving is graphics memory, not a smoother frame: it does not change the slow end-of-page frame we are working on (a layer census found nothing it removes from that frame).

## Options

### Option restart: Restart the slide

One style rule: while the menu is closed, the columns have no slide. When the menu opens again, the slide starts from its first position.

Risk: Low: one style rule.
- The visible change is the one listed: the columns restart when the menu opens again.
- Measured on Chrome and the iPhone Simulator only.

Visual difference:
- When you open the menu again, the photo columns start from their first position instead of continuing where they stopped (up to 56 px higher or lower).
- The first time you open the menu nothing differs: both start from the first position.

### Option keep-phase: Keep the slide's position

The same style rule, plus a few lines of script.
- When the menu closes, each column keeps its current position as a still picture, which needs no graphics memory.
- When the menu opens again, the slide continues from exactly that position.

Risk: Low. A short script runs once each time the menu opens or closes (it reads where 4 columns are). Measured on Chrome and the iPhone Simulator only.

Visual difference:
- None found in Chrome or the iPhone Simulator.

Option keep-phase: The same memory saving, and nothing changes on screen.
