## Problem

Stack verdict: the idle gain holds; there is no scroll gain overall; and stack5 has a candidate worst-frame regression where the #people cards start to reveal. Your swipe pick: stack5, a moderate difference, better but still a bit laggy.

The regression is in the frame right after the reveal starts.
- Phone, 16 scripted runs: stack5 median 70 ms, every run over 50 ms. Today's best: median 41 ms, no run over 50 ms.
- Excess per run (time over a smooth frame): 58 vs 21 ms. That alone outweighs everything else stack5 gains while scrolling.
- Simulator leave-one-out (Simulator figures, OBSERVED, never a phone gain): the extra work is all layer commit (Composite), and it comes from blur-cubic, not from the avatar rotator st6.

Context. These are not part of this decision; each has a track already.
- The frame that starts the reveal costs about 54 ms in both builds. Part of it may be our own probe; a probe-off read waits for a later phone slot.
- y≈2990 hero-track: fwreskip P2 (fix-scroll-engine).
- Platform gate: PR-002 (already absent in stack5).
- Three smaller spots, each one layer-commit frame of about 20-28 ms excess per run: the platform 'secure' picture starting, the first scroll frame, and #people starting to shrink. A Simulator layer diff is running now.
- Five spots under ~13 ms per run: no action.

## Options

### Option drop-blur: A: ship the stack without blur-cubic

Ship RB + st6 (the build exists, hashes checked) instead of RB + blur-cubic + st6. The cards' blur reveal keeps today's curve.
Cost: one phone block (today's best, stack5 and this build, Latin-square order, about 30 min) and no Simulator hold. Agent effort: small.

Risk: Low. This is today's reveal. Coupling: st6 still needs its selector added to RB's will-change list when it lands (fix-scroll-engine).

Visual difference:
- Nothing visible: the reveal is today's. Headless shots at 0.15 s, 0.35 s and 2 s into the reveal differ from today's by 0.11-0.14 % of pixels, within the page's own animation noise (0-0.4 %).
